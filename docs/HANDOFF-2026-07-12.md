# Handoff — 2026-07-12: exllamav3 parity pass (MTP quant, KL orientation)

## Intent

Bring ezexl3 up to feature parity with turboderp-org/exllamav3's advancements
over the last few months, including new work on the exllamav3 **dev** branch.
The WebUI is the primary interface; every new capability should land as a
dashboard form that fronts a CLI subcommand (WebUI = frontend, CLI = backend).

Parity target is **upstream** (turboderp-org) only. The locally installed
exllamav3 at `/home/unstable/exl3/private/exllamav3` is UnstableLlama's fork
with QLoRA/training work on top of merged upstream — QLoRA features will be
added to ezexl3 **later**, deliberately not in this pass. Use the fork's
`upstream/master` and `upstream/dev` git refs as the reference.

## What we did

### 1. MTP tensor quant-only stage (`ezexl3 mtp` + dashboard MTP tab)
Wraps upstream's new `util/convert_mtp.py` (dev branch, `mul1` codebook
default). Quantizes just the MTP head from a base HF checkpoint into a
standalone `.safetensors` that can be dropped alongside a legacy quant's
weights to enable MTP speculative decoding.

- `ezexl3/vendor/convert_mtp.py` — vendored from upstream **dev** with the
  standard attribution header; tracked in `VENDOR_MANIFEST.json` (the online
  staleness test now watches the dev URL for this file).
- `ezexl3/mtp.py` — runner: streams the vendored script as a subprocess.
  Output defaults to `<model>/mtp-quant/mtp_<bits>bpw.safetensors` — a
  subdirectory on purpose, so quantized MTP tensors never sit next to the
  base model's own safetensors (duplicate tensor keys would break loading).
  Skips if the output file already exists (checkpoint-style).
- `ezexl3/cli.py` — `mtp` subparser (`-m`, `-mb` default 4, `-o`, `-d`) and
  dispatch (placed before the heavy `ezexl3.repo` import).
- WebUI: `mtp` added to `valid_commands` in `ezexl3/ui/server.py`; MTP entry
  in `ui/static/js/commands.js`; nav button in `ui/static/index.html`.
- Tests: `tests/test_mtp.py` (parser, dispatch, command construction,
  skip-if-done, vendor manifest presence, UI wiring).

**Verified live**: dashboard form generates `ezexl3 mtp -m <dir> -mb 4 -d 0`
and the run endpoint spawns it; real conversion of Qwen3.5-0.8B's MTP head at
4bpw on GPU 1 succeeded (per-tensor rmse ≈ 0.0036, 10 MB output file).

### 2. KL divergence orientation fix
Per turboderp's guidance, model **A is now the quant** and model **B the
base**, so the recorded `KL divergence (A, B)` is KL(quant ‖ base).
Previously reversed. Changed in both call sites:
`ezexl3/measure.py` (`run_model_diff`) and `ezexl3/repo_measure.py`
(`_worker_measure` kl phase). No tests pinned the old order; no UI/README
labels encode the direction.

**Verified live** on Llama-3.2-3B 4bpw (GPU 1, r=10):
KL(quant‖base) = 0.01492 vs old direction 0.01521 — sane, and confirms the
directions genuinely differ.

⚠️ **Comparability caveat**: KL values measured before this change are not
directly comparable (KL is asymmetric). Checkpointing skips existing rows, so
a re-measured model can end up with mixed-orientation rows in one table. For
clean numbers, delete KL rows from the measurement DB and re-run `measure`.

### 3. Chat: GPT-OSS (harmony) prompt format
Ported `PromptFormat_gptoss` from upstream dev `examples/chat_templates.py`
into `ezexl3/chat/templates.py`, registered in `prompt_formats` and
`_MODE_HINTS` (`gpt-oss` / `gpt_oss` / `gptoss`). This was the only missing
format — `qwen35` already existed; `metharme`/`tekken` are local extras.

### 4. Vendored-script audit
All 8 manifest-tracked scripts are byte-identical to upstream **master**
(after accounting for the attribution headers). Three differ from **dev** by
additive-only changes, intentionally NOT re-vendored because the dev versions
need dev-only library features and the manifest tracks master:
- `model_diff.py`: dev adds `-l/--length`, `-nr`, cache-quant simulation and
  sweep modes (`-cq`, `-cca`, `-cqs`, `-cqsf`); `main()` returns kl_div_ab.
- `ppl.py`: dev adds gpt-oss/MXFP4 dequant handling, `--hf_device`.
- `perf.py`: dev doubles the warmup passes.
Re-vendor these when dev merges to master.

### 5. Environment / housekeeping
- exllamav3 fork editable-installed into **`/home/unstable/exl3/tabbyAPI/venv/`**
  (`pip install -e /home/unstable/exl3/private/exllamav3`). This is the venv
  for ezexl3/exllamav3 GPU work now. `qlora-venv` belongs to the QLoRA
  project (do not touch); `private/venv` has ezexl3 0.1.0 installed but its
  exllamav3 resolution was broken (namespace-package import failure) when
  running vendored scripts.
- ezexl3 itself is **not** pip-installed in the tabbyAPI venv — run it as
  `cd /home/unstable/exl3/private/ezexl3 && <venv>/bin/python -m ezexl3 …`,
  or `pip install -e` it (pending decision, see TODO).
- `.claude/settings.local.json` (gitignored) allowlists read-only git/file
  commands to stop permission prompt spam during exllamav3-repo exploration.
- `ezexl3/.claude/launch.json` (untracked) launches the dashboard on port
  8899 for browser preview during development.
